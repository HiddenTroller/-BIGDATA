# 관찰 기록

## Task 1
행별 membership을 한 번 구성하고 각 행을 한 번 처리해, 행의 해시 값을 모든 해당 열에 재사용했다. 추가 sparse membership 메모리는 O(nnz), 즉 행렬에서 1인 항목 수에 비례이며 signature는 O(문서 수×해시 수)다.
signature 길이가 band 수로 나누어떨어지지 않으면 ValueError로 거부한다. 남은 값을 버리지 않아 모든 band를 동일한 길이로 유지한다.
S1–S4는 해시 2개에서 추정 1.0, 실제 2/3이다. 해시 수를 늘리면 추정 분산이 줄지만 signature 메모리와 최솟값 갱신 시간이 증가한다.

## Task 3
n_hash=120, b=30, r=4: step=(1/30)^(1/4)=0.4273, P(candidate|s=0.6)=1−(1−0.6^4)^30=98.4456%. step을 0.6보다 낮춰 누락을 줄였고 원래 harness에서 recall 100%, 비교 125회(99.9944% 감소)를 얻었다.
같은 120개 해시를 b=10, r=12로 바꾸면 step=0.8254, P(s=0.6)=2.1556%; 실제 recall이 29.75%로 떨어졌다. 후보 확률 식은 독립적인 이상적 minhash 가정이며 사용한 선형 해시는 실용적 근사다.
해시 비용을 점수에서 제외해도 작은 n, 거대한 어휘·signature, 대형 bucket에서는 시간·메모리가 지배적일 수 있다. 실제 벤치마크 실행 시간도 확인하고 원본 similarity 호출로 최종 판정해 false positive를 제거했다.
