# 과제 3 · 희소 구조를 이용한 PageRank 최적화

### 1. 개선하려는 문제

기준 구현 `DenseMatrix`는 노드 쌍마다 전이 확률을 저장하는 n×n 행렬을 만든다. 실제 링크가 없는 위치도 0으로 저장하며, 각 반복에서 모든 행과 열을 순회한다.

기준 그래프는 노드 1,200개와 링크 5,877개로 밀도가 약 0.4081%이다. 실제 연결은 매우 적지만 행렬은 1,440,000개 위치를 보유한다. 이 과제는 같은 PageRank를 계산하면서 이 불필요한 저장과 순회를 줄이는 것이 목적이다.

### 2. R1: 구현한 클래스와 인터페이스

`YourPageRank(beta=0.85, tol=1e-10, max_iter=100)` 클래스를 구현했다.

| 메서드·속성 | 역할 |
|---|---|
| 생성자 | beta, tol, max_iter를 저장 |
| `run(graph)` | 점수를 계산하고 `{node: rank}` 반환 |
| `memory_floats()` | 동시에 필요한 float 수의 보수적 집계 반환 |
| `self.iterations` | 실제 수행한 반복 횟수 기록 |

입력 그래프의 인접 리스트를 직접 사용하며 별도 전이 행렬이나 링크별 실수 가중치를 만들지 않는다. 계산은 이전 점수 사전과 다음 점수 사전 두 개로 진행한다.

### 3. 계산 과정과 dead end 처리

1. 모든 노드의 점수를 1/n으로 초기화한다.
2. 나가는 링크가 없는 노드들의 점수 합을 구한다.
3. 순간이동과 dead end 재분배를 합친 공통 값을 계산하여 다음 점수 사전을 초기화한다.
4. 실제 존재하는 링크만 순회하며 각 목적지에 점수를 누적한다.
5. 이전·다음 점수의 L1 차이가 tol보다 작으면 종료한다.

노드 수 n, 링크 수 E일 때 반복당 작업량은 O(n+E)이다. 전체 그래프와 점수의 구조적 저장량도 O(n+E)이며, 반복당 n²개의 노드 쌍을 방문하지 않는다.

### 4. R2: 기준 구현 유지

`bench.py`와 `DenseMatrix`는 변경하지 않았다. 기준 구현의 알고리즘이나 측정 방식을 바꾸어 개선 비율을 높이지 않고 동일한 입력과 기본 파라미터로 비교했다.

### 5. R3: 점수 일치 검사

검증은 최고 순위 노드만 비교하지 않고 모든 노드의 점수를 비교한다.

`worst = max(abs(mine[v] - reference[v]) for v in reference)`

측정한 최대 차이는 약 1.180e-15였고 요구 조건 1e-9보다 작았다. 행렬 방식과 인접 리스트 방식의 덧셈 순서가 달라 부동소수점 반올림 오차가 발생할 수 있지만 이번 차이는 허용 범위 안이었다. 두 구현 모두 같은 균등 순간이동과 dead end 재분배를 사용한다.

### 6. R4: 속도와 float 수 비교

같은 그래프에서 저장한 측정 결과는 다음과 같다. 시간은 해당 실행의 단일 측정이며 재실행하면 달라질 수 있다.

| 지표 | 기준 구현 | 희소 구현 | 비교 |
|---|---:|---:|---|
| 실행 시간 | 약 0.59초 | 약 0.01초 | 원시 시간 기준 약 57.88배 빠름 |
| 보유 float 지표 | 1,440,000개 | 2,412개 | 약 597.01배 적음 |
| 점수 합 | 약 1 | 약 1 | 점수 보존 |
| 노드별 최대 차이 | 기준 | 약 1.180e-15 | 1e-9 조건 통과 |

속도 5배 이상, float 수 100배 이상 감소라는 strong 조건을 해당 측정에서 만족했다. 정확한 시간과 비율은 `out/benchmark.json`, 출력 기록은 `out/bench.txt`에 저장했다.

`memory_floats()`는 두 점수 벡터에 해당하는 최대 약 2n개와 스칼라 임시값에 대한 여유 12개를 포함해 `2*n+12`로 집계한다. 이는 float 수에 대한 보수적인 지표이지 실제 최대 메모리 사용량을 프로파일링한 값은 아니다. 인접 리스트의 문자열과 링크, 사전의 객체 비용은 이 float 지표에 포함되지 않는다. 따라서 597배라는 수치를 전체 RAM 절감 비율로 해석해서는 안 된다.

### 7. R5: 모든 노드에 더하는데 왜 큰 행렬이 필요 없는가

순간이동에서는 모든 노드에 같은 값 `(1-beta)/n`을 더하고, dead end 재분배에서도 같은 값 `beta*dangling_mass/n`을 더한다.

전체 노드를 한 번 순회하면서 공통 스칼라를 배분하면 되므로 O(n) 작업으로 처리할 수 있다. 모든 출발지와 목적지 쌍의 값을 저장하는 n×n 행렬이나 O(n²) 순회는 필요 없다. 모든 노드를 방문하는 것과 모든 노드 쌍을 방문하는 것은 작업량이 다르다.

### 8. 검증과 해석

`python bench.py --yours`로 점수·시간·float 지표를 비교했고, `python test_tasks.py --task 3`의 자동 검사도 통과했다. 순간이동 설명은 사람이 평가하는 항목이므로 `out/observation.md`에도 작성했다.

실험은 링크가 적은 과제 그래프에서 희소 표현의 이점을 확인한 것이다. 성능 비율은 그래프의 밀도, 크기, 실행 환경과 구현에 따라 달라진다.
