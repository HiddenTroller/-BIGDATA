# Week 5 관찰

## Task 1
dead end의 점수는 고장 버전에서 사라지며, 정상 버전은 전체 노드에 균등 재분배한다.
순간이동은 spider trap 밖으로 나갈 확률을 제공한다. β는 링크 이동 확률, 1−β는 균등 순간이동 확률이다.

## Task 2
β가 커지고 허용 오차가 엄격해질수록 수렴 반복 횟수가 증가했다. 상세 수치와 상위 10개 변화는 convergence.md에 기록했다.
노드 수를 16.67배 늘려도 반복 횟수는 크게 달라지지 않았지만 시간은 증가했다. 수렴률과 반복당 작업량은 다른 요인이다.

## Task 3
입력 인접 리스트(노드 식별자 및 링크)와 두 점수 사전을 사용하며 n×n 전이 행렬과 링크별 float 가중치를 만들지 않는다. 전체 구조는 O(n+E), 점수 float는 최대 2n에 스칼라 임시값 여유 12개를 더해 보수적으로 집계했다.
순간이동과 dead end 재분배는 모든 노드에 같은 스칼라를 더하는 O(n) 연산이다. 모든 노드 쌍의 값을 저장하거나 n×n 행렬을 곱할 필요가 없다.
노드별 최대 차이는 1.180e-15이며 1e-9 기준을 통과했다. 연산과 합산 순서에 따른 부동소수점 반올림 차이다. 속도 57.88배, float 수 597.01배 개선으로 strong 조건을 만족했다.
float 수 지표는 실제 프로세스 RAM 사용량이 아니며 사전/문자열/링크의 객체 비용을 포함하지 않는다. bench.py와 DenseMatrix는 변경하지 않았다.

선택 과제 Task 4는 요청에 따라 수행하지 않았다.
