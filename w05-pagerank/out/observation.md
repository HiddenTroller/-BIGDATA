# Week 5 관찰

## Task 1 — 점수 보존과 trap 탈출

고장 버전은 나가는 링크가 없는 노드의 점수를 다음 반복에 전달하지 않는다. 과제의 DEAD_END 그래프에서는 모든 경로가 C로 끝나므로 점수가 0으로 사라졌고, 정상 버전은 dead end 점수 합을 전체 노드에 균등 재분배하여 합 1을 유지했다.

SPIDER_TRAP에서는 순간이동이 없으면 C와 D가 전체 점수를 차지했다. 정상 버전은 확률 1−beta로 전체 노드 중 하나를 선택하도록 하여 A와 B에도 각각 약 0.0375와 0.0694의 점수가 남았다. beta는 링크 이동 확률이고 1−beta는 균등 순간이동 확률이다.

Dead end 재분배는 점수 유출을 막고 순간이동은 trap 밖으로의 이동을 가능하게 한다. 전체 노드에 균등하게 배분한다는 공통 형태를 가지지만 두 보정 항의 역할은 구분된다. 수렴은 연속 점수의 L1 차이로 판정하며 실제 반복 횟수도 기록했다.

## Task 2 — 수렴 비용과 순위 민감도

Beta 5개, 그래프 크기 2개, 허용 오차 5개의 조합으로 50회 측정했고 모든 실행은 최대 반복 한도 이전에 수렴했다. 노드 1,200개, tol=1e-10에서 beta가 0.5→0.99로 커지면 반복 횟수가 14→24회로 늘었다. 순간이동이 줄어 기존 분포의 영향이 더 오래 남는 것으로 해석한다.

노드 수가 약 16.67배 늘어도 beta=0.85, tol=1e-10의 반복 횟수는 20→21회로 비슷했지만 시간은 0.009652→0.191569초로 약 19.85배 늘었다. 수렴률과 반복당 노드·링크 순회 비용은 다른 요인이다. 이 조건에서 허용 오차를 두 자리씩 엄격하게 할 때 추가 한 자리당 평균 반복 비용은 약 1.5–2.5회였다.

두 그래프 모두 측정한 beta 중 0.7에서 p00000과 p00004의 상위 순서가 처음 바뀌었다. 상위 10개 집합은 같았고 순서가 달라졌다. 정확한 교차 지점은 측정하지 않았으며 발표된 순위를 비교할 때 beta와 수렴 기준도 확인해야 한다.

## Task 3 — 희소 표현과 동일한 답

n×n 행렬 대신 입력 인접 리스트와 두 점수 사전을 사용했다. 그래프와 점수의 전체 구조는 O(n+E), 반복당 순회도 O(n+E)이다. 링크별 float 가중치를 저장하지 않으며, float 지표는 두 점수 벡터의 약 2n개에 임시 스칼라 여유 12개를 더한 보수적 집계이다.

순간이동과 dead end 재분배는 모든 노드에 같은 값을 더하는 O(n) 작업이다. 전체 노드에 값을 배분하는 것만으로는 모든 노드 쌍의 n×n 행렬을 만들 필요가 없다. bench.py와 DenseMatrix는 수정하지 않았다.

모든 노드를 비교한 최대 점수 차이는 약 1.180e-15로 허용 기준 1e-9를 통과했다. 합산 순서에 따른 반올림 차이이며, 측정에서는 약 57.88배 빠르고 보유 float 지표는 약 597.01배 적어 strong 조건을 만족했다. 이 비율은 단일 실행 및 float 지표의 비교이고 전체 프로세스 RAM 절감 비율은 아니다.
