# 과제 3 · 같은 군집을 더 적은 거리 계산으로 구하기

### 1. R1–R2: 구현과 기준 유지

`task3_fewer.py`의 `YourKMeans(k, max_iter)`는 `run(points, initial_centroids, distance)`로 레이블과 중심을 반환한다. 기준 구현과 동일한 초기 중심·평균 계산·동률 규칙을 사용하며 `bench.py`는 수정하지 않았다. 중심 사이 거리와 중심 이동량도 전달받은 distance 함수로 계산하여 호출 수에 포함한다.

### 2. 경계의 의미와 가지치기

점 x의 현재 소속 중심을 a라고 할 때 다음 값을 저장한다.

- u: 현재 중심까지 거리의 상한
- l: 다른 모든 중심까지 거리의 하한
- s[a]: 현재 중심과 다른 중심 사이 최소 거리의 절반

u < max(l, s[a])이면 다른 중심으로 바뀔 수 없으므로 비교를 생략한다. 코드에서는 기준선의 동률 허용 오차를 보호하기 위해 `u + 1e-10 < max(l, s[a])`를 사용한다. 실패하면 현재 중심까지 거리를 다시 재어 u를 조이고 한 번 더 검사한다. 여전히 실패하면 모든 중심과 비교한다.

중심 이동 후 u에는 소속 중심 이동량을 더하고, l에서는 모든 중심 중 최대 이동량을 빼되 0 미만은 0으로 둔다. 삼각부등식에 의해 상한·하한을 유지하는 갱신이다. 증명된 불필요한 비교만 생략하며 근사 군집화를 하는 것이 아니다.

### 3. R5: 저장량과 유지 비용

점마다 u와 l 두 수를 저장하므로 n=20,000에서 추가 경계는 40,000개 수다. 두 구현에 공통인 레이블은 별도다. 중심별 s와 이동량은 O(k)이며 O(nk) 크기의 점-중심별 하한 행렬은 저장하지 않는다.

경계 저장량은 O(n+k)다. 라운드마다 경계 갱신 O(n), 중심 분리 계산 O(k²)와 이동량 계산이 필요하다. 평균 중심 갱신 비용과 실제로 비교하는 거리 계산 비용은 여전히 남는다. 따라서 전체 반복 비용이 단순히 O(n+k²)로 끝나는 것은 아니다.

l은 경쟁 중심과의 간격을, s는 중심 사이 분리를 이용한다. 두 조건 중 더 강한 것을 max로 결합한다. 중심 이동이 작아지면 경계가 오래 유지되어 많은 점을 건너뛸 수 있다. 추가 측정에서는 기존 알고리즘의 조건과 거리 호출을 바꾸지 않고, 가지치기 성공 시 두 조건이 각각 성립하는지 집계했다.

| 성공 시점 | l 조건만 성립 | s 조건만 성립 | 두 조건 모두 성립 |
|---|---:|---:|---:|
| 현재 중심 거리 재계산 전 | 443,889 | 213,511 | 66,692 |
| 현재 중심 거리 재계산 후 | 37,572 | 4,626 | 1,728 |
| 합계 | 481,461 | 218,137 | 68,420 |

가지치기에 성공한 점-반복은 총 768,018건이다. l만으로 성공한 경우가 s만으로 성공한 경우보다 많아, 이 데이터에서는 경쟁 중심까지의 하한 l이 더 많은 성공 사례를 담당했다. 두 조건이 동시에 성립한 68,420건을 어느 한쪽에 중복 배분하지 않았다. 이 집계는 같은 실행 안에서의 조건 성립 횟수다. 경계를 제거한 별도 비교 실험도 아래에 추가했다.

추가 실행에서 기준·원본·계측 버전의 레이블과 중심은 정확히 일치했다. 기준 호출 수는 10,320,000회, 원본과 계측 버전은 모두 1,222,968회였고 SSE는 모두 10737882.944550687, 반복은 43회였다. 계측용 집계가 결과나 거리 호출을 바꾸지 않았음을 확인했다.

### 4. R3–R4: 정확성과 호출 수

20,000개 점, 20차원, k=12에서 저장된 측정 결과다.

| 지표 | 기준 구현 | 경계 기반 구현 |
|---|---:|---:|
| 거리 호출 수 | 10,320,000 | 1,222,968 |
| SSE | 10737882.944550687 | 10737882.944550687 |
| 반복 횟수 | 43 | 43 |

거리 호출은 약 88.15% 감소했다. SSE 차이는 0으로 요구 조건 0.1% 이내를 만족하며, 호출 수 감소도 strong 기준인 70% 이상이다. 같은 배정을 바꿀 수 없는 비교만 제거하고 초기화·동률·평균 계산을 유지했기 때문에 결과를 보존한다.

성능 측정 실행 시간은 기준 구현 18.392초, 경계 기반 구현 2.785초였다. 별도 자동 검사 실행에서는 각각 17.78초와 2.65초였다. 시간 차이는 서로 다른 실행의 측정이며 호출 수·SSE·반복 횟수는 동일하다. 시간 개선을 모든 기기의 보장으로 해석하지 않는다.

### 5. 첫 반복과 추가 검증

첫 반복은 유효한 경계가 없어 20,000×12=240,000번의 거리를 계산했다. 최적화 전체 1,222,968회의 약 19.62%다.

중복 중심·빈 클러스터·동률 등을 포함한 62개 추가 사례에서 레이블과 중심까지 기준선과 일치했다는 기록이 있다. 자동 검사에서는 SSE 일치와 호출 감소가 통과했으며 R5의 설명은 사람 평가 대상이다.

### 추가 검증 · 경계를 제거한 비교 실험

같은 seed=246의 20,000개 점·20차원·k=12와 같은 초기 중심으로 네 가지 방식을 실행했다. l만 쓰는 버전은 중심 사이 분리 s의 계산도 생략했다. s만 쓰는 버전은 기존 갱신 구조를 유지하고 가지치기 조건에서 l을 제외했다. 그 외 배정·동률·평균 갱신은 유지했다.

| 방식 | 거리 호출 수 | 기준 대비 감소율 | 반복 |
|---|---:|---:|---:|
| 기준 구현 | 10,320,000 | — | 43 |
| l과 s 모두 사용 | 1,222,968 | 88.15% | 43 |
| l만 사용 | 1,287,512 | 87.52% | 43 |
| s만 사용 | 7,424,326 | 28.06% | 43 |

네 실행 모두 SSE는 10737882.944550687이고 레이블·중심이 기준 구현과 정확히 일치했다. l을 제거하면 결합 버전보다 호출이 6,201,358회 늘고, s를 제거하면 64,544회 늘었다. 따라서 이번 데이터에서는 l이 주된 절감 효과를 내고 s가 추가 개선을 제공했다.

이 차이는 해당 구현의 경계를 제거했을 때 생기는 순효과다. 경계 유지 비용과 중복해서 생략할 수 있는 비교가 있으므로 두 효과를 독립적인 절감량처럼 더하지 않는다. s만 쓰는 버전에도 사용하지 않는 l의 유지 작업이 남아 있어 실행 시간의 최적 구현 비교로 해석하지 않는다. 두 경계의 전체 결합 성능과 정확성, 거리 호출 수를 비교한 실험이다. 추가 실험들은 같은 컴퓨터에서 일부 병행했으므로 실행 시간은 일반적인 속도비의 근거로 사용하지 않았다.
